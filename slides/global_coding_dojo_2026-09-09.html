Coding Dojo

  • Dojo: a safe place to learn and practice your art
  • Coding dojo: a safe place to learn and practice coding
  • Safety: kindness, respect, TDD, mob programming, etc.
  • Schedule: usually the second Wednesday of the month
  • Info at globalcodingdojo.org

Working Agreements

  • Everything is optional — you can always pass, no explanation needed
  • Everyone gets a turn at the keyboard — if they want
  • Asking is contributing: “I don’t understand” is valuable information
  • Kindness and respect, always
  • Nobody here judges anyone’s skill level
What else do you need to feel safe here?

How the Mob Works

  • The driver — operates the keyboard, doesn’t decide what to type
  • Everyone else is a navigator — the group decides, out loud
  • One navigator is the timekeeper — tracks time on their watch or phone
  • We rotate every 4 minutes: the driver returns to the group and the next person steps in
Tip: the driver is the group’s hands. It tends to flow better when they wait for the idea to be said out loud.

The TDD Cycle

1. Red

WRITE A FAILING TEST

→

2. Green

THE SIMPLEST CODE THAT MAKES IT PASS

→

3. Refactor

CLEAN UP WITHOUT BREAKING ANYTHING

and again, one test at a time

We never write code without a test that asks for it.

Turn-Sized Prompts

  • We ask for one step, not the whole project
  • One failing test at a time — the TDD cycle already gives you the size
  • If Claude works for more than one turn, the prompt was too big
  • Interrupting is fine: Esc, and we ask for something smaller
While Claude writes, the mob doesn’t wait: read, review, and decide the next step.
